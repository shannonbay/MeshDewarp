## 1. Overall architecture

You’ll implement the four stages from the paper as an Android pipeline:

1. **YOLOv8‑seg (TFLite)**: document mask detection.
2. **Mask post‑processing**: guided filter + Otsu threshold → binary mask.
3. **Geometry restoration (OpenCV)**: contour, corners, sides, cubic grid.
4. **Remapping**: displacement map + bicubic remap → dewarped bitmap.

`DewarpProcessor.process()` will orchestrate these steps synchronously or on a background thread.

## 5. Implement mask refinement and binarization

### 5.1 Guided filter (approximation)

The paper uses a guided filter to refine the mask using the original image as guidance.

On Android:

- You can:
  - Implement a **simple guided filter** in Kotlin/Java, or
  - Approximate with **edge‑preserving blur** using OpenCV (e.g., `edgePreservingFilter` or bilateral filter).

Minimal version:

1. Convert `probMask` to OpenCV `Mat` (`CV_32F`).
2. Apply a **small radius** bilateral filter or guided filter implementation.
   - Radius ≈ `1%` of min dimension, as in the paper.

### 5.2 Otsu threshold

Use OpenCV:

1. Convert refined mask to `CV_8U` grayscale (0–255).
2. Call:

```kotlin
Imgproc.threshold(refinedMat, binaryMat, 0.0, 255.0, Imgproc.THRESH_BINARY + Imgproc.THRESH_OTSU)
```

This yields `Mbinary(x, y) ∈ {0,1}`.

---

Refinements to Step 5 (Guided Filter)
Warning: The standard OpenCV-android SDK often omits the ximgproc module which contains the GuidedFilter.

Recommendation: If you don't want to compile a custom OpenCV NDK, use the Bilateral Filter (Imgproc.bilateralFilter).
The paper uses the Guided Filter specifically to preserve edges while smoothing the segmentation mask—a Bilateral Filter does exactly this and is available in the base Imgproc package.

## 6. Contour extraction and document sides

### 6.1 Extract largest contour

1. `findContours` on `binaryMat`.
2. Choose the contour with **maximum area**.
3. Approximate contour with Douglas–Peucker:

```kotlin
Imgproc.approxPolyDP(contour, approxContour, epsilon, true)
```

Where `epsilon` is a fraction of perimeter (e.g., `0.01 * arcLength`).

### 6.2 Corner detection and ordering

1. Compute convex hull (`convexHull`).
2. Extract hull points as candidate corners.
3. Compute center of mass:

```kotlin
val center = Point(meanX, meanY)
```

4. Sort points by angle from center relative to positive Y‑axis (or X‑axis) to get consistent order (e.g., top‑left, top‑right, bottom‑right, bottom‑left).

### 6.3 Segment contour into four sides

Following the paper’s idea:

1. Use the four corners to split the contour into four segments:
   - `S1`: between corner1 and corner2
   - `S2`: corner2 → corner3
   - `S3`: corner3 → corner4
   - `S4`: corner4 → corner1
2. For each side `Si`, store the ordered list of points.

## 7. Construct the topological 2D grid

Refinements to Step 7 & 8 (Cubic Fitting & Grid)This is the "secret sauce" of the paper. Here are two technical nuances to watch for:Solving Intersections (The k-d Tree): The paper uses a k-d tree to find the intersection of horizontal and vertical cubic lines. On Android, implementing a full k-d tree might be overkill.Optimization: Since your grid is relatively small (e.g., 50x50), a Brute Force Nearest Neighbor search is often faster on mobile CPUs than the overhead of building a k-d tree for every single frame.Parametric vs. Explicit: You mentioned fitting $f(x) = ax^3 + bx^2 + cx + d$.Watch out: This fails if a side is perfectly vertical (infinite slope).Fix: Fit the lines parametrically relative to the side length $t \in [0, 1]$. Fit one polynomial for $x(t)$ and one for $y(t)$. This handles vertical and horizontal curves with the same logic

### 7.1 Interpolate between opposite sides

For vertical grid lines (left–right):

- For each parameter `α ∈ [0,1]` (e.g., 0, 1/N, …, 1):
  - Interpolate between corresponding points on left and right sides:

\[
L_i(\alpha) = (1 - \alpha) P_i^{left} + \alpha P_i^{right}
\]

Similarly for horizontal lines (top–bottom).

Implementation:

- Sample N points along each side (e.g., 50–100).
- Use linear interpolation between matching indices.

### 7.2 Smooth coordinates (Savitzky–Golay)

- Implement a 1D Savitzky–Golay filter or approximate with a small polynomial smoothing over the sequence of points.
- Apply separately to x and y sequences of each line.

### 7.3 Fit cubic polynomials

For each grid line:

- Fit:

\[
f_i(x) = a_i x^3 + b_i x^2 + c_i x + d_i
\]

using least squares.

On Android:

- Use a small linear algebra routine (e.g., your own normal equations solver or a tiny matrix library) to solve for coefficients.
- Alternatively, fit polynomials in parametric form (x(t), y(t)) with cubic splines instead of explicit `y=f(x)`—this is often easier in practice.

## 8. Grid intersections and displacement map

### 8.1 Compute intersections

For each pair of perpendicular grid lines (one from vertical family, one from horizontal family):

- Solve `f_v(t_v)` and `f_h(t_h)` intersection.
- In practice, you can:
  - Sample points along each curve.
  - Use nearest‑neighbor search (k‑d tree in the paper) to find closest intersection points.

On Android:

- Implement a simple k‑d tree or:
  - Use a grid of sampled points and nearest‑distance search (good enough for mobile).

You end up with a 2D array `Gdistorted[i][j] = (x_ij, y_ij)`.

### 8.2 Build uniform target grid

Create a uniform rectangular grid `Guniform[i][j]` over the document’s width and height:

- `x_uniform = i * (W / (Nx - 1))`
- `y_uniform = j * (H / (Ny - 1))`

### 8.3 Compute displacement map

For each grid node:

\[
\Delta x_{ij} = x_{distorted,ij} - x_{uniform,ij}
\]
\[
\Delta y_{ij} = y_{distorted,ij} - y_{uniform,ij}
\]

Then interpolate these displacements to full image resolution using cubic interpolation.

Implementation:

- Store displacement as two `Mat` objects (`dx`, `dy`) or a single 2‑channel `Mat`.

## 9. Bicubic remapping to produce the dewarped bitmap

The "Map" Size: mapX and mapY are CV_32FC1 matrices. For a standard 12MP camera photo, these maps alone will take up ~48MB each (Total 96MB).

Advice:
1. Perform all the "math" (Steps 4–8) on a downscaled version of the image (e.g., 1024px max side).
2. Upscale the resulting displacement grid to the full resolution.
3. Apply Imgproc.remap only once at the very end. This keeps your UI responsive and avoids OutOfMemoryError.

Use OpenCV’s `remap`:

1. Build `mapX` and `mapY`:

```kotlin
val mapX = Mat(height, width, CvType.CV_32F)
val mapY = Mat(height, width, CvType.CV_32F)

// For each pixel (x, y):
// mapX[y, x] = x + dx[y, x]
// mapY[y, x] = y + dy[y, x]
```

2. Call:

```kotlin
Imgproc.remap(
    srcMat,
    dstMat,
    mapX,
    mapY,
    Imgproc.INTER_CUBIC,
    Core.BORDER_CONSTANT
)
```

3. Convert `dstMat` back to `Bitmap` and return.

This corresponds to:

\[
I'(x, y) = I(x + \Delta x(x, y), y + \Delta y(x, y))
\]

## 10. Wire it all into DewarpProcessor.process()

Here’s a high‑level sketch of the final `process`:

```kotlin
class DewarpProcessor(
    private val yoloModel: YoloSegmentationModel
) {

    fun process(original: Bitmap): Bitmap {
        // 1) Run YOLOv8 segmentation (TFLite)
        val probMask: Bitmap = yoloModel.predictMaskBitmap(original)

        // 2) Refine mask (guided / bilateral filter) + Otsu threshold
        val binaryMaskMat = refineAndBinarizeMask(probMask)

        // 3) Extract contour, corners, and sides
        val contourData = extractContourAndSides(binaryMaskMat)

        // 4) Build topological grid (cubic polynomials)
        val gridData = buildTopologicalGrid(contourData, original.width, original.height)

        // 5) Compute displacement map and remap
        val dewarped = remapWithDisplacement(original, gridData)

        return dewarped
    }
}
```

Each helper (`refineAndBinarizeMask`, `extractContourAndSides`, etc.) maps directly to a section of the paper.
